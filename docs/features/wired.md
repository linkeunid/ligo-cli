# Wired codegen

`ligo g wired` (alias `ligo g wire`) replaces runtime reflection-based DI
with a static, compile-time wired graph — comparable to
[google/wire](https://github.com/google/wire) but with **zero coupling
to the Ligo import path**. The user writes an injector file guarded by
`//go:build wireinject`; the generator emits a parallel `wired_gen.go`
(built without that tag) whose function body wires every factory in
topological order.

## Why

Ligo's default DI is 100% reflection at runtime: at startup the
container scans factories via `reflect`, builds a dependency graph,
and instantiates each provider. That's flexible during development but
has three costs in production:

1. Every resolve goes through reflection overhead.
2. Missing dependencies and cycles surface as runtime panics, not
   compile errors.
3. The dependency graph is invisible — you can't `go to definition`
   from a factory parameter to the provider that satisfies it.

Wired codegen flips all three: the generated file is plain Go calling
plain functions, mistakes fail at `ligo g wired` time, and the wiring
is readable source.

## Author the injector

```go
//go:build wireinject

package wired

import "github.com/your-org/app/internal/app"

func Build() (*app.Server, error) {
    return nil, wire(
        app.NewConfig,
        app.NewLogger,
        app.NewDatabase,
        app.NewUserService,
        app.NewServer,    // last factory's return value becomes Build's first return
    )
}

// wire is the user-defined marker. ligo-cli replaces Build's body in
// the generated counterpart; this function is never invoked at runtime.
func wire(_ ...any) error { return nil }
```

The marker function name is fixed (`wire`) so the parser stays simple.
Define it once as a stub returning `error`.

## Generate

```bash
ligo g wired                    # scans internal/wired/
ligo g wired internal/bootstrap # scans a different package
ligo g wired --dry-run          # preview without writing
```

What the generator does:

1. Loads the package with the `wireinject` build tag active.
2. Locates `Build` and the inner `wire(...)` call.
3. Resolves each argument's function signature, builds a dependency
   graph keyed by Go types, and topologically sorts it. Cycles and
   missing providers fail at codegen time with a clear error.
4. Emits `<pkg>/wired_gen.go` guarded by `//go:build !wireinject`. The
   body assigns each factory's result to a local variable, threads
   dependencies through the parameter list, and returns the last
   factory's value paired with `nil`.

Example output for the injector above:

```go
// Code generated by ligo-cli; DO NOT EDIT.
//go:build !wireinject

package wired

import "github.com/your-org/app/internal/app"

func Build() (*app.Server, error) {
    config := app.NewConfig()
    logger := app.NewLogger()
    database := app.NewDatabase(config, logger)
    userService, err := app.NewUserService(database, logger)
    if err != nil {
        return nil, err
    }
    server := app.NewServer(userService, logger)
    return server, nil
}
```

## Build modes

```bash
# Default — uses the generated wiring
go build ./...

# Iteration — builds against the wireinject stubs (forces the original
# Build body, which calls wire(...) and panics, useful only when you
# want to verify the marker compiles)
go build -tags=wireinject ./...
```

Add `//go:generate ligo g wired` to a project file so
`go generate ./...` keeps the wired file in sync as part of normal
codegen.

## Integration with `ligo serve` / `ligo work`

`ligo serve` and `ligo work` auto-detect a wired package (default
`internal/wired/`) and regenerate `wired_gen.go` before launching. In
`--watch` mode the regen also runs on every restart, so the generated
wiring tracks edits to the injector without a manual `ligo g wired`.

Opt out per-invocation:

| Flag | Effect |
|------|--------|
| `--no-wired` | Skip the regen step |
| `-n` | Short form |
| `-nw` | Combined: watch on (`-w`), regen off (`-n`) |

## Constraints (v0.11.x)

- Marker function name is fixed: **`wire`**. Define it once as a stub
  returning `error`.
- Each factory must return `T` or `(T, error)`.
- Every parameter type must be satisfied by another factory in the
  list or by a named injector parameter.
- The codegen does **not** import or reference
  `github.com/linkeunid/ligo`. It operates on whatever types the
  factories return. You decide whether the root value is `*ligo.App`,
  your own composition root, or any other type.

## When to use it

- **Use wired** for the composition root of a production app —
  one-time wiring at process start where you want speed and
  compile-time safety.
- **Skip wired** for the dynamic Ligo module tree, request-scoped DI,
  or per-feature `HookedFactory` chains. The runtime DI handles those
  better.

The two coexist fine: wire your `*ligo.App` (or your service
container) at the composition root via codegen, then let Ligo's
runtime DI manage everything inside the modules.
